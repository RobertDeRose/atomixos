## Delivered Capability

The provisioning service's live OpenAPI document is a supported client contract. Public API routes declare stable
operation IDs, domain tags, request bodies, authentication headers, success/error responses, and typed schemas, while
Boot UI, static assets, and implementation-only routes remain excluded.

## User-Facing Behavior

Online clients can discover how to request a nonce, upload or validate config, poll jobs, and interpret typed responses
and errors. The schema documents provisioned-device SSH signature headers and first-boot behavior without implying an
unauthenticated post-provision mutation path.

## Design Integration

Schema metadata stays next to explicit Litestar route wiring and typed domain schemas. Focused tests inspect the live
document generated by the application, so framework defaults cannot silently become public contract.

## Operational Impact

Clients may generate bindings from the live schema but still use `config.toml` or bundles as canonical desired-state
artifacts. Schema compatibility must be reviewed whenever public routes, payloads, authentication, or errors change.

## Design Reconciliation

### Delivered as Designed

Public route inventory, stable metadata, binary config bodies, auth-header documentation, typed responses/errors, and
non-public route exclusion were delivered.

### Intentional Changes

The contract is documented through existing provisioning, runtime, and data-flow pages rather than a separate API
chapter. The live document remains the exact machine-readable reference.

### Deferred Work

A pre-existing Litestar deprecation warning for an inferred typed job path parameter remains non-blocking and does not
change the schema contract.

### Rejected or Removed Scope

Boot UI routes in OpenAPI, OAuth/JWT solely for schema access, and replacement of `config.toml` as the canonical artifact
remain out of scope.
