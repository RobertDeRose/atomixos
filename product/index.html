Every update is atomic. Every boot is identical. Any failure finds ground state.

Atomic, from the Greek atomos: indivisible. AtomixOS is a NixOS-based operating system for single-board computers. Describe a device in one config.toml, and every update lands whole in a spare slot, or not at all, taking over only after it proves itself healthy.

Twenty-five elements. One stable compound.

Six families bond into one device, from the flake that builds the image to the fleet that runs it. Pick an element to see what it contributes.

Nix flake
The whole OS comes from one pinned Nix flake. Same inputs, same bits: build it today or next year and you get the same image.
Squashfs root
The root filesystem is compressed and read-only. Runtime changes land in a tmpfs overlay and vanish on reboot, so drift never builds up.
Build policy
Watchdog, provisioning transport, and fleet settings are fixed at build time in a validated build.toml. Every image carries a copy and its provenance in /etc/atomixos.
config.toml
Users, SSH keys, network, firewall, update server, and every container live in one config.toml. Version it, review it, reuse it.
Config bundle
Need files too? Pack config.toml with a files/ directory into a .tar.gz or .tar.zst. Containers mount the payloads through ${FILES_DIR}, read-only by default.
Bootstrap console
A fresh device serves a drag-and-drop web page on port 8080. Drop in a config or a bundle and watch it apply. No tools required.
USB seed
Put config.toml on a labeled USB stick, plug it in, and power on. The device provisions itself on first boot.
Provisioning API
A typed REST API validates, applies, and patches configuration as tracked jobs. Each device publishes its own OpenAPI description at /schema/openapi.json.
Signed changes
After first boot, every change is signed with an admin's SSH key over a single-use nonce. No passwords or API tokens to leak.
Export
Download the live configuration as a bundle and import it on the next device to clone a setup.
Quadlets
Declare containers, networks, volumes, and image builds in config.toml. AtomixOS renders them as Podman Quadlets and runs them as systemd services, rootful or rootless.
Activation policy
Name the services that must come up. If a change leaves them down, the device restores the previous configuration on its own.
Durable logs
rsyslog writes host and container logs to /data, so the evidence survives reboots and rollbacks.
A/B slots
Two complete copies of the system. Every update goes to the one that is not running.
RAUC bundle
Updates ship as signed RAUC bundles and are verified before a single byte reaches the eMMC.
Update polling
The device checks your update server every hour, with random jitter so a fleet never stampedes it. Set the server in config.toml.
Health check
A new slot must keep its services, network, and containers healthy for 60 seconds before it is committed.
Rollback
Three boots that never prove healthy, and U-Boot falls back to the slot that worked. No site visit needed.
Watchdog
Turn on the hardware watchdog and a hung kernel resets the board. The reset counts toward rollback.
LAN gateway
The LAN port hands out addresses, answers DNS, and serves time to the devices behind it.
Firewall
The WAN side is closed by default. Open exactly the ports you need in config.toml.
Isolation
IP forwarding is off. Devices on the LAN never reach the internet through AtomixOS.
Zero credentials
No default passwords and no shared keys. Each device gets its own credentials when you provision it, as EN 18031 expects.
SSH keys only
SSH accepts keys only, root login is off, and SSH on the WAN side stays closed until you turn it on.
Nixstasis
Enroll devices with Nixstasis to provision them remotely and reach them through outbound tunnels, without opening a port on the device.

Two isotopes. Zero decay.

Slot A and slot B are the same element at different versions: the device runs from one while the next is written beside it, so a power cut mid-update never leaves it without a working system. Your configuration and logs never decay: they live on /data, and no update touches them.

How an update lands

  1. Write the spare slot

    A signed RAUC bundle is verified, then written to the slot that is not running.

  2. Boot into it

    U-Boot switches to the new slot and counts the attempt.

  3. Prove it is healthy

    Services, the network, and your containers must stay healthy for 60 seconds before the slot is committed.

  4. Or fall back

    After three boots that never prove healthy, U-Boot returns to the slot that worked.

From bare board to fleet in one file

  1. Flash

    Write the image to the eMMC with mise run flash.

  2. Describe

    Users, firewall, and containers go in one config.toml, like the one beside this list.

  3. Provision

    Drop it on the bootstrap console at port 8080, a USB stick, or the boot partition.

  4. Change

    Sign API calls with your SSH key. Each change runs as a job and rolls back if it fails.

  5. Scale

    When one device becomes a hundred, enroll them with Nixstasis.

Provisioning covers every source, the signed API, and exports.
